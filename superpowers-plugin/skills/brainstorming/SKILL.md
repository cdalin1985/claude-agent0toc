# Brainstorming

## Overview

Don't commit to the first idea. Generate options. Evaluate trade-offs. Then decide.

**Core principle:** The first idea is rarely the best idea, but it's hard to see alternatives once committed.

## When to Brainstorm

- Starting a new feature
- Facing a non-trivial design decision
- Stuck on an approach
- After a failed attempt
- Before writing code

## The Process

### 1. Define the Problem
- What are we trying to accomplish?
- What are the constraints?
- What does success look like?
- What's the actual question?

### 2. Generate Options
- Aim for 3-5 distinct approaches
- Include obvious ones AND unconventional ones
- Don't filter yet - quantity first
- Consider doing nothing as an option

### 3. Evaluate Trade-offs
For each option:
- Pros and cons
- Implementation complexity
- Maintenance burden
- Risk level
- Reversibility

### 4. Decide
- Recommend one option
- State the main reason
- Note what could change the decision
- Get buy-in before committing

## Tips for Good Brainstorming

- Start broad, narrow later
- Question assumptions
- Look for analogies in other domains
- Consider "what would this look like in 5 years?"
- Ask "what's the simplest thing that could work?"
- Ask "what's the riskiest thing we could try?"

## Common Pitfalls

- Falling in love with first idea
- Generating only similar options (all variations of A)
- Not considering "do nothing"
- Over-engineering before validating need
- Solo brainstorming when collaboration helps
